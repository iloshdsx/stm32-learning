## 一、定位与导航（第 1 课 ✅）

| 命令 | 大白话 | 什么时候真的会用到 |
|---|---|---|
| `pwd` | 我现在在哪 | 迷路了看一眼；写脚本时需要"当前路径" |
| `ls` | 这儿有什么 | 进到一个陌生目录，第一件事就是 `ls` |
| `ls -l` | 看得更细：权限、大小、修改时间 | 排查"为什么这个文件跑不起来"（多半是权限）；看文件大小 |
| `ls -a` | 连隐藏文件也列出来 | 找 `.bashrc`、`.git`、`.gitignore` 这类带点的隐藏文件 |
| `ls -la` | **两个一起用**，日常最常用 | 既看细节又看隐藏文件 |
| `cd 路径` | 走到那个目录 | 进项目目录、进日志目录 |
| `cd`（不带参数） | **回家**（`/home/zhy`） | 走丢了想快速回起点 |
| `cd ..` | **上一层** | 一层层往上退 |
| `cd -` | 回到上一次待的目录（会打印路径） | 两个目录来回切换 |
| `mkdir -p a/b/c` | 建文件夹（中间层一起建） | 建项目目录结构 |
| `touch 文件` | 建一个空文件（也能更新文件时间） | 占位、测试 |
| `clear` 或 `Ctrl+L` | 清屏（终端显示错乱时用 `reset`） | 屏幕太乱看不清 |

### 补充：`pwd` 和 `ls` 到底差在哪

| | `pwd` | `ls` |
|---|---|---|
| 回答 | **我在哪**（位置） | **这儿有什么**（内容） |
| 全称 | Print Working Directory | list |
| 输出 | **一个路径**，永远只有 1 个 | **一列名字**，0 个到几百个都行 |
| 能看别处吗 | ❌ 只能报"你现在站哪儿" | ✅ `ls /etc`，人不用动 |
| 比喻 | 看门牌号 | 看屋里有什么 |

- 空目录里 `ls` **什么都不显示**——不是出错，是目录空的。
- 迷路时的标准动作：**`pwd` 确认位置 → `ls` 看内容**，两个连着用。

### 补充：`mkdir` 和 `touch` 到底差在哪

| 命令 | 造什么 | 比喻 | 能不能装东西 |
|---|---|---|---|
| `mkdir 名字` | **文件夹** | 盒子 | ✅ 只能装东西，不能写字 |
| `touch 名字` | **空文件** | 纸 | ❌ 只能写字，装不了东西 |

**对照实验（敲一遍就永远分得清了）**

| 操作 | 结果 |
|---|---|
| `cd 文件夹` | ✅ 进得去（目录本来就是给人进的） |
| `cd 文件` | ❌ `Not a directory` |
| `cat 文件夹` | ❌ `Is a directory` |
| `cat 空文件` | ✅ **不报错**，只是什么都不显示（空文件是合法的） |

> `touch` 碰到**已经存在**的文件**不会清空内容**，只把"最后修改时间"刷成现在。
> 它的名字就是"碰一下"——造空文件只是副业。
> 一眼分辨：`ls -l` 第一列，`d` = 目录，`-` = 文件。

## 二、必须记住的两个符号

| 符号 | 含义 |
|---|---|
| `~` | 家目录 = `/home/zhy` |
| `..` | 上一级目录；`.` 是当前目录 |
| `/` | 根目录；路径从 `/` 开头叫**绝对路径**，否则叫**相对路径**（相对当前位置） |
### 空格规则（一句话：**空格 = 分词符**）

shell 看到空格就**切一刀**，每一段是一个独立的"词"：
**第 1 段 = 命令名（要执行谁）；后面的每一段 = 参数（对它做什么、对谁做）。**

| 写法 | shell 切成几段 | 结果 |
|---|---|---|
| `cd ~/learn` | `cd` + `~/learn` | ✅ 两段，正常 |
| `cd~/learn` | `cd~/learn`（一段） | ❌ 命令名被粘住了 |
| `mv b.txt c.txt` | 3 段 | ✅ |
| `mv b.txt.c.txt` | 2 段（只有一个参数） | ❌ `mv` 不知道要搬到哪 |
| `mkdir -p ~/a` | 3 段 | ✅ |
| `mkdir -p~/a` | 2 段 | ❌ `-p~` 成了一个词 |

**三个地方不要加空格**

1. **引号里面**：`echo "hello world"` 里 `"hello world"` 算**一个**词——引号把空格保护起来了
2. **路径 / 文件名内部**：`linux/file-ops` 是一个整体，不能断开
3. **`=` 两边**：赋值写 `a=1`，不写 `a = 1`

**例外：运算符不需要空格**

`>` `>>` `|` `<` `;` 这些是 shell 的**运算符**，本身就是分隔符，前后空格**可有可无**：
`echo "2" >list.txt` 和 `echo "2" > list.txt` 一样能跑。

但 `-l` 这种**参数（选项）**是给命令的"词"，**必须**用空格隔开：`wc -l` ✅ / `wc-l` ❌。
> **一句话记法**：命令行就像 `命令 词 词 词`，**词与词之间一定有空格**。
> 回车前扫一眼：有没有哪两段粘在一起了？粘住就把它们掰开。

## 三、读懂 `ls -l` 与文件权限（第 1 课复习 ✅）

### 1. 一行 `ls -l` 分成七列

| 列 | 例子 | 含义 |
|---|---|---|
| 1 | `-rw-r--r--` | **文件类型 + 9 位权限** |
| 2 | `1` | 链接数 |
| 3 | `zhy` | 所有者 |
| 4 | `zhy` | 所属组 |
| 5 | `0` | 大小（**字节**） |
| 6 | `Oct  5 22:44` | 最后修改时间 |
| 7 | `a.txt` | 文件名 |

### 2. 第 1 位 = 文件类型

| 符号 | 含义 |
|---|---|
| `-` | 普通文件 |
| `d` | 目录 |
| `l` | 软链接（快捷方式） |
| `c` | 字符设备（**串口 `/dev/ttyUSB0` 就是它，调 STM32 会碰到**） |

### 3. 后 9 位 = 权限，用「谁 × 什么」两个维度读

**第一步：切三刀**（每 3 个字符一组）

```
-  rw-  |  r--  |  r--
  所有者   同组    其他人
```

**第二步：每组内部的顺序是固定的 = 读、写、执行**

| 谁 | 读 | 写 | 执行 |
|---|---|---|---|
| 所有者 | 位置 1 | 位置 2 | 位置 3 |
| 同组 | 位置 4 | 位置 5 | 位置 6 |
| 其他人 | 位置 7 | 位置 8 | 位置 9 |

> 只看位置 **3、6、9**，就知道谁能执行。

### 4. 只有四个符号

| 符号 | 含义 | 数字 |
|---|---|---|
| `r` | read，读 | 4 |
| `w` | write，写 | 2 |
| `x` | execute，执行 | 1 |
| `-` | 没有这个权限 | 0 |

### 5. `x` 对"文件"和"目录"是两回事（面试爱问）

| 对象 | `x` 的含义 |
|---|---|
| 普通文件 | 能不能当程序**运行**（`./t.exe`） |
| **目录** | 能不能**进去**（`cd`） |

同理，目录的 `r` = 能不能**列出**里面有哪些文件（`ls`）。
所以权限是 `r--` 的目录：能 `ls` 看到文件名，但 `cd` 不进去。

### 6. 两个易错点

1. **目录的"大小"不是里面文件的总和**：空目录也显示 4096 字节，那是目录自己的索引表，跟内容无关。
2. **别凭记忆读权限**：看到权限串，第一个动作是**加竖线切三刀**，再一个一个读。

### 7. 高级符号（知道有这回事就行）

| 符号 | 含义 | 例子 |
|---|---|---|
| `s` / `S` | setuid：运行时临时获得文件所有者的身份 | 系统的 `passwd` |
| `t` / `T` | 粘滞位：只有自己能删自己的文件 | `/tmp` = `drwxrwxrwt` |

## 四、权限数字速查（0~7）✅

### 1. 为什么权限是"八进制"

一组权限是 **3 个二进制位**（读/写/执行），两两组合正好 8 种情况（0~7）。
而**八进制的一位就是三个二进制位**——所以 3 组权限刚好写成 3 个八进制数字，一位对一组，不用换算。

### 2. 数字 ↔ 符号 对照表（背下这一张就够）

| 数字 | 二进制 | 符号 | 含义 |
|---|---|---|---|
| **7** | 111 | `rwx` | 读 + 写 + 执行 |
| **6** | 110 | `rw-` | 读 + 写 |
| **5** | 101 | `r-x` | 读 + 执行 |
| **4** | 100 | `r--` | 只读 |
| **3** | 011 | `-wx` | 写 + 执行 |
| **2** | 010 | `-w-` | 只写 |
| **1** | 001 | `--x` | 只执行 |
| **0** | 000 | `---` | 什么都不能 |

### 3. 怎么算：4 = 读、2 = 写、1 = 执行，**相加**

| 符号 | 计算 | 数字 |
|---|---|---|
| `rwx` | 4 + 2 + 1 | 7 |
| `rw-` | 4 + 2 | 6 |
| `r-x` | 4 + 1 | 5 |
| `r--` | 4 | 4 |
| `---` | — | 0 |

### 4. 反过来读：看到数字就拆成 4 + 2 + 1

| 数字串 | 拆分 | 符号 | 人话 |
|---|---|---|---|
| `750` | 7 / 5 / 0 | `rwx` `r-x` `---` | 全能 / 能读能执行 / 碰不了 |
| `600` | 6 / 0 / 0 | `rw-` `---` `---` | 只有自己能读写 |
| `644` | 6 / 4 / 4 | `rw-` `r--` `r--` | 自己读写，别人只读 |

### 5. 常见权限一览（记 5 个就够用）

| 数字 | 符号 | 谁能干什么 | 典型场景 |
|---|---|---|---|
| **777** | `rwxrwxrwx` | 所有人全能 | **不要用**，等于把门拆了 |
| **755** | `rwxr-xr-x` | 自己全能；别人能读、能进 | 目录、可执行脚本 |
| **700** | `rwx------` | 只有自己全能 | 私人目录 |
| **644** | `rw-r--r--` | 自己读写；别人只读 | 普通文件默认值 |
| **600** | `rw-------` | 只有自己能读写 | **SSH 私钥**、密码文件 |

> ⚠️ 以后配 SSH key，私钥**必须**是 `600`，否则 SSH 拒绝工作，报 `permissions are too open`。

### 6. 口诀

> **4 读、2 写、1 执行；三位一组，相加成数。**
> **看符号先切三刀，看数字就拆 4+2+1。**

> 📌 改权限用 `chmod`，写法就是 `chmod 644 文件名`（第 3 课讲）。

### 7. 今天自己算出来的三串（2026-10-05 动手算过 ✅）

| 权限串 | 数字 | 谁 → 能干什么 |
|---|---|---|
| `-rwxr-x---` | **750** | 所有者全能；同组能读、能执行；其他人什么都干不了 |
| `-rw-r--r--` | **644** | 所有者能读能写；同组、其他人只能读（普通文件的默认值） |
| `-rw-------` | **600** | 只有所有者能读能写；其他两个人碰都碰不了（**SSH 私钥必须这样**） |

> 这三串都是照同一个流程算出来的：**切三刀 → 每组按 `rwx` 对位 → 4 / 2 / 1 相加**。
> 看到别人给的数字（比如 600、755），也可以倒着拆回符号，再念出"谁能干什么"。

## 六、提效技巧

1. **`Tab` 自动补全**：`cd ~/l` + `Tab` → 补成 `cd ~/learn/`。少打字、还不容易拼错。
2. **`↑` 上箭头**：调出上一条命令，改一改再回车。
3. **忘了参数**：`ls --help` 或 `man ls`。不用背，会查就行。
4. **每天开工 60 秒「热身三连」**：`pwd` → `ls` → `cd 到当天要用的目录`。
   命令靠手指记，天天碰一次就一辈子不忘。
5. **打错了？不要重打 —— 按 `↑`**：上箭头调出上一条命令，改那一个字母再回车。
   这是全篇**最省时间**的一招，比背任何快捷键都有用。
6. **`Ctrl+R` 反向搜历史**：按 `Ctrl+R`，输入 `chmod`，它会把以前敲过的命令捞出来，回车直接用。
7. **`!!` = 上一条命令**：单独敲 `!!` 就是重复上一条；`sudo !!` = 把上一条命令用管理员身份重跑一遍。
8. **打错的四步处理**（照这个走，省一半力气）：

| 情况 | 怎么办 |
|---|---|
| 刚敲完，还没回车 | 用**退格**改，别整条删了重打 |
| 已经报错了 | 按 `↑` 调出来改那一个字母，**别重打整条** |
| 忘了以前是怎么敲的 | `Ctrl+R` 搜关键词 |
| 命令很长 | **复制粘贴**（WSL 里 `Ctrl+Shift+V` 或鼠标右键） |

> Linux 对拼写**零容忍**：少一个空格、字母顺序颠倒，都会报错。
> 会用 Linux 的人不是"从不打错"，而是**打错了不重打**。

## 七、最容易踩的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `mkdir -p~/learn/linux` → `error: unexpected argument '-~' found` | Linux 里**空格是分隔符**，`-p` 和 `~` 粘在一起就被当成一个词了 | 写成 `mkdir -p ~/learn/linux`（`-p` 后要有空格） |
| `cd~/learn/linux` → `-bash: cd~/learn/linux: No such file or directory` | 同上，整串被当成"要执行一个叫这个名字的文件" | 写成 `cd ~/learn/linux` |
| `ls` 什么都不显示 | 不是出错，是**目录是空的** | 正常现象 |
| 终端里出现一堆 `\350\205\276` 之类乱码 | 不小心把**中文**粘进终端了 | `Ctrl+C` 或 `reset` 清掉重来 |
| 权限读错（把 `r--` 读成 `r-x`） | 凭记忆扫一眼，没有真的看字符 | **先切三刀再读** |
| `cd~` → `Command 'cd~' not found` | 还是空格：`cd` 和 `~` 粘成一个词了 | 写成 `cd ~`，或者干脆只敲 `cd` |
| `cd ~learn/linux` → `No such file or directory` | `~` 后面**必须紧跟 `/`**。`~learn` 被解释成"用户 learn 的家目录"，可没这个人 | 写成 `cd ~/learn/linux` |
| **`command not found`** | = **没有这个命令**。命令名拼错，或者命令名和参数粘成了一坨（`cd~`、`echohi`） | 看报错里那个"词"是不是你要敲的命令；数空格 |
| **`No such file or directory`** | = **没有这个文件/目录**（它没说命令有问题）。常见三种：① 路径拼错（`filr-ops`）② 文件名带 `/` 被当成路径（`cd/learn/...`）③ 要操作的文件还没被造出来（`mv b.txt` 但还没 `cp`） | 先 `pwd` 看我在哪，再 `ls` 看这儿有什么 |
| `ls-1` → `ls-1: command not found` | 两个坑叠一起：① `ls` 和 `-1` 之间**没空格** ② `-l` 是**小写字母 L**（long 的首字母），不是**数字 1**——等宽字体里这俩长得几乎一样 | 写成 `ls -l`；记法：`-l` = **l**ong（长格式） |
| `echo"hi"> a.txt` → `echohi: command not found`，但**反而多出一个空 a.txt** | `echo` 和 `"hi"` 之间没空格，被粘成了命令名 `echohi`；那个空文件是 `>` **先**建好的（重定向比命令本身先执行） | 写成 `echo "hi" > a.txt` |
| `mv b.txt.c.txt` → `missing destination file operand` | 两个文件名之间没空格，`mv` 只收到**一个**参数，它不知道要搬到哪 | 写成 `mv b.txt c.txt` |
| `mv b.txt c.txt` → `cannot stat 'b.txt'` | **命令有先后**：`b.txt` 还没被 `cp a.txt b.txt` 造出来，不存在的东西没法搬 | 报错先 `ls` 看现在有什么，再按顺序补 |

> **自查口诀**：敲命令前先数空格。结构永远是 `命令` + 空格 + `参数`。
> **第二条**：`~` 后面永远紧跟 `/`（`~/learn`）。粘成 `~learn` 会被当成"用户 learn 的家目录"。
> **第三条**：看到 `-` 就是**选项**，它前面**一定**有空格——`-l`、`-name`、`-p`、`-c` 都是**独立的词**。

## 十、文件操作三兄弟 + 往文件里写（第 2 课 ✅ 动手跑通）

### 1. 三兄弟对照表（记住"原件在不在"）

| 命令 | 英文 | 干什么 | 跑完之后 |
|---|---|---|---|
| `cp a.txt b.txt` | copy 复印 | 复制出一份 | **两份**：`a.txt` 和 `b.txt`，原件在 |
| `mv b.txt c.txt` | move 搬 | 改名 / 挪位置（同一个命令） | **只剩 `c.txt`**，`b.txt` 没了 |
| `rm c.txt` | remove 移除 | 删除 | 没了，**没有回收站** |

> `mv` 一个命令管两件事：目标还是同一个目录 = **改名**；目标带别的路径 = **搬家**。
> 说到底它俩是同一个动作——文件换了个名字/位置，文件本身还是那一个。

### 2. 往文件里写：`echo "内容" > 文件名`

| 命令 | 干什么 |
|---|---|
| `echo "hi" > a.txt` | 把 `hi` 写进 `a.txt`（**覆盖**：原内容全没了） |
| `echo "hi" >> a.txt` | 追加到末尾（**不覆盖**，以后详讲） |
| `cat a.txt` | 把文件内容打印出来看 |

> ⚠️ **`>` 比命令本身先执行**：就算命令名写错了，文件也已经被建好了（空的）。
> 今天那个凭空多出来的 `a.txt` 就是这么来的。
>
> **今晚实测**：`echo "2" >> list.txt` 之后 `cat` 还是 4 行（旧的都在）；
> 换成 `echo "2" > list.txt` 之后 `cat` **只剩 1 行**——前面全被冲掉了。

### 3. 命令有先后（今天实测的因果链）

```
echo 造出 a.txt  →  cp 复印出 b.txt  →  mv 把 b.txt 改名成 c.txt  →  rm 删掉 c.txt
```

提前跑 `mv b.txt c.txt` 就会报 `cannot stat 'b.txt'`——因为 `b.txt` 还不存在。
**报错先 `ls`**：先看清目录里现在有什么，再决定敲什么。

### 4. 今天实测的输出（照着核对）

```
$ echo "hi" > a.txt ; ls   →   a.txt
$ cp a.txt b.txt    ; ls   →   a.txt  b.txt     ← 两份，原件在
$ mv b.txt c.txt    ; ls   →   a.txt  c.txt     ← 还是两份，名字变了
$ rm c.txt          ; ls   →   a.txt            ← 少一个，找不回来
```

### 5. `rm` 安全三原则

1. **删之前先 `ls`**：确认要删的确实在，别的手滑删错
2. **能写全路径就写全**：`rm ~/learn/linux/file-ops/c.txt`，别在一个没看清的目录里删
3. **别拿 `rm -rf` 练手**：`-r` = 连目录一起删，`-f` = 不问我直接删
## 十一、重定向与管道（第 3 课 ✅ 动手跑通）

### 1. 一句话原理

每个命令默认都是 **从屏幕收、往屏幕送**。重定向和管道，就是改这个"往哪送"：

```
命令  ──结果──▶  屏幕              默认（你一直看到的）
命令  ──结果──▶  文件              > 覆盖写、>> 追加写
命令A ──结果──▶  命令B 的输入       | 管道（不落盘、不上屏幕）
```

### 2. `>` 和 `>>`

| 写法 | 干什么 | 危险点 |
|---|---|---|
| `ls -l > list.txt` | 结果写进文件，**先清空**再写 | ❗旧内容全没了 |
| `echo "x" >> list.txt` | 追加到文件末尾 | 安全 |
| `cat list.txt` | 把文件内容打到屏幕 | 只读，最安全 |

> 实测（2026-10-05）：`>>` 之后 `cat` 出 4 行（旧的都在）；换成 `>` 之后**只剩 1 行**。

### 3. `|` 管道

`命令A | 命令B` = 把 A 的**输出**直接当作 B 的**输入**（不落文件、不上屏幕）。

| 例子 | 意思 |
|---|---|
| `ls \| wc -l` | 数"这个目录里有几个东西"（实测 = 2） |
| `ls -l \| wc -l` | 同上（注意 `ls -l` 第一行 `total` 也会被数进去） |
| `history \| tail -5` | 看最近 5 条命令 |

> 管道能**一直往后接**：`命令A | 命令B | 命令C`——这就是 Linux 最有名的"用积木搭命令"。

### 4. 顺带记住：`>` 先动手

shell **先**把输出文件建好（空文件），**再**去执行命令。
所以 `ls -l > list.txt` 的结果里会包含 `list.txt` 自己，而且大小是 **0** 字节。

### 5. 一个完整例子（验收时亲手做的）

```bash
ls -l / > root.txt      # ① 屏幕上什么都没有 —— 列表全进文件了
echo done >> root.txt   # ② 把 done 追加到末尾
tail -3 root.txt        # ③ 看最后 3 行
```

```
drwxr-xr-x  12 root root 4096 ... usr    ← 旧的（① 写进去的）
drwxr-xr-x  13 root root 4096 ... var    ← 旧的
done                                     ← 新的（② 追加的）
```

前两行是**原来就有的**，第三行是**新加的** → 证明 `>>` 没冲掉旧内容。
如果第 ② 步用的是 `>`，这里就只剩一个 `done`。

> **为什么要学**：屏幕是**临时**的（一滚就没了），文件是**永久**的。
> 输出太多看不清、要留证据、要事后慢慢查——都靠 `>` `>>` 存进文件。
## 十二、命令也是文件：`/usr/bin` 探索 ✅

### 1. 看文件四兄弟（全都只读，最安全的一课）

| 命令 | 干什么 | 记忆 |
|---|---|---|
| `cat 文件` | 一口气全打出来（**只适合小文件**） | cat = 把内容吐出来 |
| `head 文件` | 只看**开头**（默认 10 行）；`head -3` 就是 3 行 | head = 头 |
| `tail 文件` | 只看**结尾**（默认 10 行） | tail = 尾巴 |
| `less 文件` | **分页**看，大文件专用 | 老笑话：less 比 more 更强 |

> **`less` 里只要记三个键**：`空格` 往下翻页、`/关键词` 搜索、**`q` 退出**（卡住就按 `q`，这是新手第一救命键）

### 2. `/usr/bin` 是什么

系统的**命令都住在 `/usr/bin`**——每个命令就是一个**可执行文件**。

```bash
ls /usr/bin > big.txt
wc -l big.txt        # 实测 905 → 这台机器上有 905 个命令
head -30 big.txt     # 看前 30 个
tail -30 big.txt     # 看后 30 个
```

### 3. 意外发现：`gnu*` 家族

`ls /usr/bin` 里能看到自己刚学的命令，还带个 `gnu` 前缀：

```
gnuls  gnurm  gnumv  gnuhead  gnutail  gnucat  gnupwd  gnumkdir  gnuwc  ...
```

原因：这套 Ubuntu 正在把老版 **GNU coreutils** 换成 Rust 重写的 **uutils** 版，
于是把**原版改名成 `gnu*`** 留在系统里保底。装软件时那句提示就是证据：

```
command 'chmod' from deb coreutils-from-gnu    (0.0.0~ubuntu25)
command 'chmod' from deb coreutils-from-uutils (0.0.0~ubuntu25)
```

> 看某个命令住在哪：`which ls` → `/usr/bin/ls`
> GNU 版**不叫** `ls`，而叫 `gnuls`（独立命令）；看它得敲 `type -a gnuls`

### 4. 以后会用到的（先认个脸，不用记）

| 命令 | 干什么 |
|---|---|
| `xxd` | 把文件按**十六进制**打出来（看协议帧、二进制数据） |
| `readelf` `objdump` `nm` `strip` `addr2line` | 分析编译出来的二进制；调 STM32 用的是 ARM 版：`arm-none-eabi-objdump` |
| `pyserial-miniterm` | 串口终端——**以后看 STM32 的串口打印就用它** |
| `screen` | 终端复用（一个窗口开多个会话） |
### 5. 三个新发现（2026-10-05 实测）

**① 你敲的 `ls` 其实是个别名（alias）**

```bash
type -a ls
# ls is aliased to `ls --color=auto'
# ls is /usr/bin/ls
# ls is /bin/ls
```

第一行说明：`ls` 真正执行的是 **`ls --color=auto`**——所以目录名一直是**蓝色**的。
单独敲 `alias` 能看到所有别名（里面通常有 `ll` = `ls -alF`、`la`、`l` 这些省事写法）。

**② `/bin` 和 `/usr/bin` 是同一个地方**

`/bin` 是个**软链接**，指向 `/usr/bin`。敲 `ls -l /` 能看到：

```
lrwxrwxrwx   1 root root     7 ... bin -> usr/bin
└─ 类型位是 l（软链接，第 3 节学过）
```

所以 `type -a ls` 里那两条路径，其实是**同一个文件**。

**③ `gnu` 版是独立命令，不是"第二个 ls"**

`gnuls`、`gnurm` 是自己的命令名，所以 `type -a ls` 看不到它们；要看就敲 `type -a gnuls`。
### 6. 根目录导游 + `ll` 别名 + `/tmp` 的 `t`（2026-10-05 实测）

**① 三个省事别名（`alias` 输出里就有，直接用）**

| 别名 | 等于 | 说明 |
|---|---|---|
| `ll` | `ls -alF` | **最常用**：长格式 + 隐藏文件 + 分类标记 |
| `la` | `ls -A` | 列出全部（含隐藏），不带详情 |
| `l` | `ls -CF` | 多列紧凑 |

> 想临时不用别名：`\ls`（前面加反斜杠）或者写全路径 `/usr/bin/ls`。

**② `/tmp` 的 `t` —— 第 3 节学的粘滞位，亲眼看到了**

```
drwxrwxrwt   6 root root     120 ... tmp
        └─ t = 粘滞位
```

`/tmp` 谁都能写，但**只能删自己的文件**——所以它才敢对所有人开放。

**③ `/` 根目录导游**

| 目录 | 是什么 | 嵌入式会用到吗 |
|---|---|---|
| `/home` | 用户的家（你的 `~` 就在这） | 天天用 |
| `/etc` | 系统的**配置文件**都在这 | 改设置、配串口 |
| `/var/log` | **日志** | 出问题翻这里 |
| `/dev` | **设备文件**：串口 `/dev/ttyUSB0` 就在这里 | ⭐ STM32 一定碰 |
| `/tmp` | 临时文件，重启清空 | 存临时数据 |
| `/proc` `/sys` | 内核的"窗口"，**只读**（类型位后是 `r-xr-xr-x`） | 看系统状态 |
| `/bin` `/usr/bin` | 命令住的地方 | 第 4 课学过 |

> 目录名的英文来历见 **九.5 目录名的英文溯源**。

**④ 四条软链接（类型位都是 `l`）**

```
bin -> usr/bin     lib -> usr/lib     lib64 -> usr/lib64     sbin -> usr/sbin
```

所以 `type -a ls` 里的 `/usr/bin/ls` 和 `/bin/ls` 是**同一个文件**。
## 十三、找东西：`grep` 与 `find`（第 5 课 ✅ 动手跑通）

### 1. 分工完全不同

| 命令 | 找什么 | 一句话 |
|---|---|---|
| `grep` | **文件里的内容**（哪一行含这个词） | 找内容 |
| `find` | **文件本身**（按名字找文件） | 找文件 |

### 2. `grep 关键词 文件`

| 写法 | 意思 |
|---|---|
| `grep apt big.txt` | 打出所有含 `apt` 的行 |
| `grep -c apt big.txt` | `-c` = count，只报"有几行" |
| `grep -n apt big.txt` | `-n` = number，带行号 |
| `grep -i apt big.txt` | `-i` = ignore case，忽略大小写 |
| **`grep -rn "关键词" 目录`** | `-r` = recursive，在一个目录的所有文件里递归找——**以后看代码全靠它** |

> `grep` 全名 **g**lobal **r**egular **e**xpression **p**rint（全局 / 正则 / 打印），第 9 节记过。

### 3. `find 从哪找 -name "名字"`

```bash
find ~/learn -name "*.txt"     # learn 下的所有 .txt
find /usr/bin -name "gnu*"     # 所有 gnu 开头的命令
```

⚠️ **引号不能省**：加了引号，`*` 才是"通配模式"交给 `find`；不加引号会被 shell 先自己展开，意思就变了。

### 4. 通配符 `*` 和 `?`（今天实测搞清楚的）

| 模式 | 意思 | 实测结果 |
|---|---|---|
| `*` | **任意个**任意字符（包括 0 个） | — |
| `*.txt` | 任意名字 + `.txt` 结尾 | 6 个文件 ✅ |
| `.txt`（没有 `*`） | 名字**就是** `.txt` → 只能匹配隐藏文件 | **一个都没有** |
| `gnu*` | 以 `gnu` **开头** | 104 个 `gnu` 版命令 |
| `*gnu` | 以 `gnu` **结尾** | `perl5.40-x86_64-linux-gnu` 之类 |
| `?` | 恰好**一个**字符 | 以后用 |

> `*` 代表"一串"（可以是 0 个字符），`?` 代表"一个"。**星号在哪一侧，就管哪一侧。**

### 5. 实测记录（2026-10-06）

- `find ~/learn -name "*.txt"` → 6 个：`review/a.txt`、`review/b.txt`、`note.txt`、`file-ops/a.txt`、`file-ops/big.txt`、`file-ops/list.txt`
- `find /usr/bin -name "gnu*"` → 104 个，里面有 `gnuchmod`、`gnuchown`、`gnucp`、`gnumv`、`gnurm`、`gnumkdir`、`gnucat`、`gnuwc`、`gnuhead`、`gnutail`、`gnuls`……

> 这正是你敲错 `chomd` 时，Ubuntu 提示的 `coreutils-from-gnu` 的**实物**。
## 十四、数数工具 `wc` + 看行号（2026-10-06 补充）

### 1. `wc` 是什么

> `wc` = **w**ord **c**ount（数字数）。数文件里有**多少行、多少词、多少字节**。

⚠️ **`wc` 没有 `-n` 这个选项**，敲 `wc -n` 会报 `invalid option -- 'n'`。想要行号是 `grep -n` / `cat -n`（见下面第 4 条）。

| 选项 | 英文 | 数什么 |
|---|---|---|
| `-l` | **l**ines | **行数**（最常用，第 3 课 `\| wc -l` 用的就是它） |
| `-w` | **w**ords | 单词数（按空格分） |
| `-c` | bytes | **字节数** |
| `-m` | characters | **字符数**（中文用这个） |
| `-L` | longest | 最长的那一行多长 |

### 2. 不带选项时，输出顺序是固定的

```bash
wc big.txt
```

```
   5     20    105  big.txt
   │      │     └──── 字节数 (-c)
   │      └────────── 词数   (-w)
   └───────────────── 行数   (-l)
```

**"多少行" = 输出的第一列，或者直接用 `wc -l`**

```bash
wc -l big.txt        # 只给行数 → 第一列就是
```

### 3. 三个易错点

- `-c` 是**字节**不是字符：英文 1 字符 = 1 字节，**中文 1 字 ≈ 3 字节**（UTF-8）。想数字符用 `-m`。
- `wc -l` 数的是**换行符个数**：文件最后一行**没按回车**，会比肉眼看到**少 1**。
- `wc` 常和管道搭：`命令 | wc -l` = "数这个命令输出了几行"（`|` 见第 3 课）。

### 4. 顺便：看行号的两个工具

| 命令 | 干什么 |
|---|---|
| `cat -n list.txt` | 整个文件**每行都编号**列出来 |
| `less -N 文件名` | 翻大文件时**左边显示行号** |

> 对比记忆：`grep -n` 只给**匹配的那几行**带行号；`cat -n` 是**全文件**都带行号。

**口诀**：`-l` 数行、`-w` 数词、`-c` 数字节；不带选项就是"行 词 字节"。
