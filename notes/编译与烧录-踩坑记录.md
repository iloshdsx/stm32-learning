## 1. "编译失败"其实失败在最后一行 —— 打印大小

**现象**（`烧录.bat` 的输出，注意**中间一个字都没有**）：

```
  AS  startup_stm32f103c8tx.s
  LD  test_led.elf

make: *** [Makefile:55: test_led.elf] Error 1
********** 编译失败 **********
```

看着像链接失败，但**没有任何报错文字**，这就说明"看上去像"的那个判断是错的。

**排查过程（思路比结论值钱）**

1. **先看产物在不在**：
   `D:\STM32\test_led_build\test_led.elf` —— **在，而且大小正常**。
   → 链接根本没失败。这一步就把 90% 的错误方向排除了。
2. **再看行号**：`Makefile:55`，去数第 55 行是什么：

   ```
   51: $(TARGET): $(OBJS)
   52: > @echo   LD  $@
   53: > @$(CC) -o $@ $(OBJS) $(LDFLAGS)      ← 链接（成功）
   54: > @echo.
   55: > @$(SZ) $@                            ← 打印大小（失败的是这行！）
   ```

3. 结论：**失败的是"打印大小表"这个锦上添花的步骤**。

**根因**：`arm-none-eabi-size` 去读刚刚才写完的 elf 文件，
被杀软 / 索引器瞬时锁住 → 偶发 `Permission denied`。
它只是打印一张表，却把整个脚本判成了"编译失败"。

**修法**：在 make 里给这行前面加一个 `-`（含义：**这步失败也别管**）

```
> -@$(SZ) $@
```

**教训（记住这两条）**

- **`make: *** [Makefile:NN: 目标] Error N` 里的 `NN` 就是"失败的那一行"**
  —— 别猜，去数行号。数完常常发现"根本不是你以为的那一步"。
- **报错是空的时候，先看产物生成了没有**：能立刻区分"真失败"和"假失败"。

## 2. ST-Link 连不上（2026-10-07 · 已解决，根因在文末）

### 现象演变（关键在这张表）

| 阶段 | 报错 | 含义 |
|---|---|---|
| 一开始 | `Error: Unable to get core ID` | ST-Link **认到了**，但连不上芯片 |
| 换线 / 调换 SWCLK-SWDIO 之后 | `Error: No debug probe detected` | **连 ST-Link 本身都找不到了** |

**报错变了 = 问题的层次变了。** 别再照着旧思路查 ——
这两个错一个在"下载器 ↔ 芯片"这一层，一个在"电脑 ↔ 下载器"这一层。

### 已经排除掉的

- **板子没坏**：板载 LED 一秒一闪 → 芯片在正常运行我们烧进去的程序
- **驱动没坏**：能读出 ST-Link 的 SN（`37FF71064E5734369C0C1A43`）和固件版本（`V2J37S7`）→ USB 通信正常
- **没被别的程序占用**：CubeIDE 虽然开着，但没有 GDB server、没有监听端口（查过 61234 等端口）

### 当时的判断

从"能认到但连不上"变成"完全找不到"，很像 **USB 连接 / 供电不稳**
—— 克隆版 ST-Link 非常吃 USB 口（前面板、扩展坞、延长线都会出问题）。

### 还没做的验证（明天接着来）

- [ ] 换机箱**后置** USB 口（不走前面板 / 扩展坞 / 延长线）
- [ ] 插到**另一台电脑**，看能不能被识别 → 能就是本机 USB 的事，不能就是 ST-Link 挂了
- [ ] **万用表**量那 4 根线的通断（到货了就做，5 秒出结论）
- [ ] 换**第二块 Blue Pill** 交叉验证（手里有两块）
- [ ] 最后手段：重启电脑复位 USB 控制器

### 顺便排除掉的坑

- `Unable to get core ID` 最常见的成因是 **SWCLK / SWDIO 插反** ——
  这两根对调**烧不了东西**，是最低成本的一次尝试，值得先做。
- **GND 最容易松、又最容易忽略**：漏了 GND，ST-Link 就是认不到板子。
- **千万别把 5V 接到板子上** —— 板子是 3.3V 的。

### 根因 & 解决（2026-10-07 凌晨 · 当场破案）

**根因：那 4 根线里 `3V3` 和 `GND` 接反了。**

等于把板子的电源正负颠倒 —— ST-Link 的 3.3V 被直接短路，电流拉爆，
ST-Link 内部电压塌掉 → 灯灭、下载器从电脑上消失。

#### 最硬的一条判据（记住这条就够）

> **ST-Link 单独插 USB 灯亮，一接上板子就灯灭 / 发烫 → 一定是短路。**
> 不用怀疑电脑、不用怀疑驱动。

**发烫 = 电流大 = 短路。** "灯灭"和"发烫"是同一件事的两种表现。

#### 现象演变全表

| 阶段 | 现象 / 报错 | 含义 |
|---|---|---|
| 一开始 | `Error: Unable to get core ID` | ST-Link **认到了**，但连不上芯片 |
| 调换 SWCLK-SWDIO 后 | `Error: No debug probe detected` | **连 ST-Link 本身都找不到了** |
| 逐渐加剧 | ST-Link 灯灭 + **发烫** | **供电被短路拉垮** |
| 修好接线 | `Device ID 0x410` ✅ | 一次通过 |

#### 逐根接法（不用万用表就能定位短路）

**先拔掉 USB 再动手**；通电时间控制在 1~2 秒，每接一根看一次 ST-Link 的灯：

1. 只接 `GND` → 灯应还亮
2. 再接 `3V3` → 灯应还亮，且板子红色 `PWR` 灯亮
   - **灯灭 / 发烫** → 这两根反了，或板子有连锡短路
3. 再接 `SWCLK` → 看灯
4. 再接 `SWDIO` → 看灯

**判据**

- `GND` + `3V3` 就出问题 → 短路在**板子**上（查排针有没有连锡）
- 加上 `SWCLK` / `SWDIO` 才出问题 → 短路在**线序**

#### 顺手学到的两条命令

```powershell
# 看电脑有没有认出 ST-Link（不用打开 CubeIDE）
STM32_Programmer_CLI.exe --list

# 只连芯片、不烧东西，验证 SWD 通不通
STM32_Programmer_CLI.exe -c port=SWD mode=normal
```

#### 今晚多排除掉的一条

- **程序没锁调试口**：`main.c` 只用了 `PC13`（灯）和 `PA0`（按键），
  **完全没碰 `PA13` / `PA14`**（SWD 的那两根）→ "程序把调试口占了"这条不成立。

#### 血的教训

- **别"整排对调"**：那不是换 `SWCLK`/`SWDIO`，是把 `3V3` 和 `GND` 一起反接，
  会烧板子 / 烧 ST-Link。
- **两块板子的丝印顺序不一定一样**，必须**按丝印一根一根接**，
  不能按"第 1 对第 1"整排对。
- 短路的代价是**发烫**，而发烫是会**真的烧掉**硬件的。
  发现发烫，第一件事永远是**拔**。

## 二、SWD 被程序自己锁死（2026-10-07 凌晨，最惨的一晚）

> **一句话记住**：烧进去之前能连（芯片里是别的程序）→ 一烧上这份 PWM 固件，
> SWD 就被程序自己掐死了。
>
> 所以判断"是程序锁的还是接触坏的"，就看**灯**：
> 大灯**呼吸** = 程序在跑 = SWD 被程序关了；大灯**不呼吸** = 能连。

### 症状

- 烧完软件 PWM 固件后，ST-Link 再也连不上：
  `Error: Unable to get core ID` / `No STM32 target found`
- 但 ST-Link 本身是好的（能读出 `SN 37FF71064E5734369C0C1A43` / `FW V2J37S7`）
- 板子也是好的：**大灯还在呼吸** → 芯片活着、程序在跑、硬件没坏
- 换线、换板子、换频率（`100 / 480 / 1000 / 4000 k`）、换模式
  （`normal / UR / hotplug`）、摘掉逻辑分析仪夹子 → **全都没用**

### 真正的根因（就一行代码）

`Core/Src/stm32f1xx_hal_msp.c` 里 CubeMX 生成的 `HAL_MspInit()`：

```c
/** DISABLE: JTAG-DP Disabled and SW-DP Disabled */
__HAL_AFIO_REMAP_SWJ_DISABLE();     /* ← 元凶 */
```

- 这句把 **JTAG + SWD 一起关掉**，`PA13/PA14` 交还给 GPIO
- 它在 `HAL_Init()` 里执行 = **上电跑第一句就把调试口掐死**
- 所以时序是：**烧进去之前能连 → 一烧上这份固件 → SWD 永久消失**
- 来源：CubeMX 里 **`SYS → Debug` 被设成了 `Disable`**
  （`.ioc` 里那行是 `VP_SYS_VS_ND.Mode=No_Debug`）

**关键判据（记死它）**

| 大灯 | 程序 | 能连 SWD 吗 |
|---|---|---|
| **呼吸** | 在跑 | ❌ 连不上（SWD 被程序关了） |
| **不呼吸** | 没跑 | ✅ 能连 |

### 怎么修

1. **改代码**（永久修）：那一行换成

   ```c
   __HAL_AFIO_REMAP_SWJ_NOJTAG();   /* 只关 JTAG，保留 SWD */
   ```

2. **改 CubeMX 源头**（否则下次"重新生成代码"又会被覆盖回来）：
   **`SYS → Debug` 改成 `Serial Wire`**

3. **反汇编验证**（改完怎么确认真的生效）：

   ```powershell
   arm-none-eabi-objdump -d test_led.elf |
     Select-String "<HAL_MspInit>:" -Context 0,40
   ```

   看写进 `AFIO_MAPR` 的常数：

   - `0x04000000`（SWJ_CFG = 100）= 全关 ❌
   - `0x02000000`（SWJ_CFG = 010）= 只关 JTAG、SWD 开 ✅

### 怎么把锁死的芯片救回来

芯片里跑着"关 SWD"的固件 → 常规连接永远失败。
**唯一出路：让芯片别跑那段程序。**

- **BOOT0 = 1**：芯片去跑出厂 bootloader（不碰 SWD）→ 就能连
  - 本板黄帽子：**拔掉 = 1**（务必用"PWR 红灯亮 + 大灯不呼吸"**两个灯一起**确认）
- **抢窗口大法**（这次真正救命的招）：
  - `BOOT0=1` 之后，能连的窗口只有**复位后的几秒**，过了就没了
  - 于是：**一边每秒按一下 `RESET`，一边让电脑连打**
    （`-c port=SWD mode=normal freq=<100/480/1000 轮换> -e all`）
  - 本次实测：**前 37 发全灭，第 38 发中**
- **一旦连上，立刻 `-e all`（全片擦除）** → 擦空就**永久解锁**了
  （芯片里没程序，就再也没人能关掉 SWD），之后想烧几次烧几次

### 这次的错判（记住，别重犯）

- ❌ 我一度断言"3.27V 说明 GND/3V3 接好了"——拔掉板子侧 4 根线后**还是 3.26V**，
  说明那电压量的是 **ST-Link 自己的电**，不算数
- ❌ "大灯不亮" ≠ BOOT0 生效：**很可能是断电**（拔帽子时把线带松了）。
  判据必须**两个灯一起看**：`PWR 红灯亮` + `大灯不呼吸` 才是真的
- ❌ 我只在 `main.c` 里搜 `PA13/PA14`，没搜到就下结论"程序没锁调试口"——
  那行其实在 **`stm32f1xx_hal_msp.c`**。
  **要搜就搜整个 `Core/Src/`，不能只看 main.c**
- ❌ 一度怀疑 Zadig 误伤、逻辑分析仪夹子压弯针、杜邦线坏了、ST-Link 烧了——
  全是错的。**根因在自己生成的代码里。**

### 以后不再踩

- 新建 CubeMX 工程**第一件事**：`SYS → Debug = Serial Wire`
- 每次烧录完**随手连一次**（`-c port=SWD mode=normal`，看到 `Device ID` 就行），
  确认调试口没被自己关掉
- 永远不要升级 ST-Link 固件（克隆版升级 = 变砖）

### 补 1：把修复做成"抗覆盖"的（重要）

只改 `msp.c:77` 不够 —— 在 CubeMX 里点一次**"重新生成代码"**，
那一行就被覆盖回 `SWJ_DISABLE()`，第二天又砖一次。

所以**再在 `USER CODE` 区里补一句**（CubeMX 会保留这段）：

```c
  /* USER CODE BEGIN MspInit 1 */
  /* 保留 SWD 调试口：若 CubeMX 再次生成出 SWJ_DISABLE()，这里再改回来。 */
  __HAL_AFIO_REMAP_SWJ_NOJTAG();
  /* USER CODE END MspInit 1 */
```

顺序很关键：生成的 `SWJ_DISABLE()` 在前，`USER CODE` 区在**后**，
所以这一句会把 SWD 再抢回来 → **以后重新生成代码也不会砖**。

验证方式（反汇编里应该能看到**两处**写 `0x2000000`、**一处也不该有** `0x4000000`）：

```powershell
arm-none-eabi-objdump -d test_led.elf |
  Select-String "<HAL_MspInit>:" -Context 0,45
```

### 补 2：另一块板子（A 板）为什么"同样接法就是连不上"

- A 板那 4 个 SWD 针**是插进孔里的，没焊**（B 板是焊死的）
- 表现：**接触在飘** —— 第 1 发能连上，中间 63 发全灭，第 64 发又中
  （典型"时好时坏"，和"程序锁了调试口"的**持续失败**完全不是一回事）
- 处置：`BOOT0=1` + **每秒按一下 `RESET`** + 电脑**连打**，
  **中一发就立刻 `-e all` + 烧写 + 校验**
- 根治：**把那 4 根针焊一下**（不焊的话以后还会偶发连不上）

### 结局（2026-10-07 中午）

- 两块板都刷上了"保留 SWD"的固件，各连 3 次全中
- `BOOT0` 黄帽子记得插回原位（= 0），否则每次上电要先等 bootloader 超时
